## 已确认的合成规则

### M1-R03：历史优惠券到期边界

只为合成夹具设置 `expires_at = 2026-11-23T10:00:30Z`，采用 `now < expires_at` 时有效、`now >= expires_at` 时过期的边界。测试验证到期前与恰好到期时点，不推导真实会员或优惠券政策。

### S1-R02：一次有界并发检查

在一个本地合成 Run 中，于开售后同时发送 101 个预约请求；每个请求使用不同的已种子化合成用户和幂等键。初始库存为 100，预期 100 个预约成功、1 个因无可用库存被拒绝；再完成这 100 个预约，检查库存守恒和订单唯一性。该检查只代表当前本机单进程 Demo 的有界 API 并发回归，不是生产数据库并发证明或负载测试。

### S1-R05：预约、完成、取消与超时

对每个库存单位采用以下合成生命周期：

1. 用户发起预约时，库存从 `available` 进入 `reserved`，创建带 Fake Clock 到期时点的待处理订单。
2. 到期前模拟完成购买时，库存从 `reserved` 进入 `sold`，订单变为 `success`；只有此状态计入每用户的一次有效成功购买。
3. 到期前取消，或 Fake Clock 到达预约期限时，预约只释放一次，库存可再次分配。为保留现有五桶模型，建议将释放作为 `reserved → released → available` 的同一原子业务动作记录；完成后 `released` 不作为不可售库存长期占用。
4. 取消或超时释放后的重试保持同一终态，不重复扣加库存；释放后再完成购买应拒绝。尚未成功购买的用户可重新预约。
5. 预约超时为 30 个模拟秒，边界使用 `now >= expires_at`。取消时立即释放；超时只由 Fake Clock 推进触发，不设置真实定时器。

`success` 是唯一有效成功购买状态。释放使用 `reserved → released → available` 两条同一原子业务动作中的不可变流水；结束后的 `released` 桶为 0，可用库存恢复。`pending_release` 在本 Demo 中保持 0。

## 范围边界

这三项只适用于固定 Seed、Fake Clock、本地合成 Run 和当前单进程内存 Demo。真实支付、生产订单、数据库跨进程并发、负载测试、队列语义与一致性 SLA 均不包含在内。
