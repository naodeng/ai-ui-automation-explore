## 1. 工具是什么，为什么 QA 应该了解？
- **一句话差异点：** Planner → Generator → Healer，从探索计划生成、维护自动化测试。
- 类型：AI 生成与维护测试；文章深度：完整篇；建议写作排期：P1。
- 目标读者：已有 Playwright/编码基础或准备建设 UI 回归的 QA。
- 与基础 Playwright Test 的关系：解释是执行工具、SDK、Agent、诊断器、评估环境还是托管基础设施，明确是否能够产出**可重复、可断言、可集成 CI 的测试**。

## 2. 适用场景与不能替代什么
- 推荐：Planner → Generator → Healer，从探索计划生成、维护自动化测试。
- **能力边界：** Healer 可能把真缺陷误判为测试失效，须有人审查。
- 明确区分：操作执行成功、业务断言成立、安全合规通过、回归持续稳定四种不同结论。

## 4. 第一个可复现的 Quick Start
- **Given**：本地 Demo 已初始化、测试账号/数据已重置。
- **When**：使用 `Playwright Test Agents` 完成页面观察 → 目标控件定位 → 安全操作 → 采集截图/日志。
- **Then**：有真实、可追踪的浏览器观察记录；有服务端只读 Oracle 时才能声称业务断言通过。
- 待补：逐条安装命令、操作步骤、关键配置、预期输出、失败排查图。

## 5. 主案例：E1｜电商优惠券与下单
- 示例业务规则：Demo：购物车小计达到 100 元时 C20 抵扣 20 元；99 元不得享受优惠；相同幂等键不能创建多个有效订单。
- **风险假设：** 金额漂移、重复下单、优惠券状态不一致。
- 测试动作（根据该工具实际能力删减）：
  1. 在 99 元与 100 元边界切换优惠券并检查 UI 与报价 API 一致。
  2. 选择优惠券后修改数量、刷新或返回购物车并重新计算。
  3. 快速重复提交订单，读取只读订单账本验证无重复订单。
- 独立验证：`checkout_quote + order_ledger + coupon_ledger`。
- 安全限制：禁止真实支付、真实发货和生产券核销。
- 输出：操作日志 / 截图 / 测试断言 / 后端只读证据 / 可复现步骤；不支持的证据标记为「需用其他工具补齐」。

## 6. 另两个案例：适用性迁移
- **M1 会员等级升级与降级**：使用测试事件将银卡升级为金卡，验证展示与服务端鉴权；要使用 `membership_authorization + membership_events + entitlement_ledger + fake_clock` 验证关键结论。
- **S1 商品秒杀**：测试开售前/开售瞬间/售罄后的按钮和排队状态；要使用 `campaign_clock + flashsale_ledger + user_order_ledger` 验证关键结论。


## 7. 从一次探索到持续 UI 自动化
- [ ] 将可重复步骤转换为明确的测试名称、前置条件、固定测试数据、稳定定位器和断言。
- [ ] 用 Playwright Test / 对应 Runner 把业务 Oracle 纳入断言，不依赖仅凭截图的模型判断。
- [ ] 明确哪些步骤是 LLM 推理，哪些步骤应使用确定性代码；至少重复执行三轮验证稳定性。
- [ ] 建立 Trace、Screenshot、Network 和 Report 的最小证据集；敏感字段脱敏。
- [ ] 在 CI 中使用环境隔离、失败证据保留和阻断/非阻断门禁。

## 10. 常见失败与排查
- 安装/版本不一致、浏览器启动失败、会话丢失、测试数据污染、元素变化/模型误判。
- 每项给出：现象 → 根因排查 → 证据 → 修复 → 回归确认；未经复现不得写成“已解决”。

## 11. 权限与安全
- 只在授权 `localhost` Demo 与允许域名测试；禁用真实支付、生产秒杀并发、危险写操作。
- Prompt Injection：页面文字与工具输出视为不可信；请求中含密码、Cookie、Token 必须脱敏。
- 如需 Cloud / 第三方模型，先审批数据流和留存策略；如支持任意代码执行，要隔离运行。
