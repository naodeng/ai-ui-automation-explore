# 三案例 × 工具：怎样评价 UI 自动化价值

## 案例角色
| 案例 | 主要质量目标 | 不可被 UI 截图替代的验证 |
|---|---|---|
| E1 优惠券下单 | 金额、优惠规则、幂等、状态一致 | 报价 API + 订单和优惠券账本 |
| M1 会员升降级 | 状态机、撤权、历史权益、缓存一致 | 服务端鉴权 + 等级事件 + 权益账本 |
| S1 商品秒杀 | 开售/售罄状态、排队、超时、重复 | 库存/订单账本 + 独立受控 API 并发实验 |

## 工具实测共用观察维度
- 安装首次成功率、环境耗时（不假设）。
- UI 自动化任务完成率、重复执行一致性、Flaky 原因。
- 断言类型：纯 DOM/截图判断还是能接入服务端 Oracle。
- Trace/Network/Console/Screenshot 可用程度和敏感信息处理。
- CI 适用性、版本固定方式、维护成本（人工处理分钟数）。
- AI 产生候选缺陷中的 Precision、复现成功率和缺陷证据完整率。
- token/API/云端浏览器成本（若适用，必须以真实账单或日志测量）。
- 执行越权和危险写操作次数（必须为 0）。

## 最小对照实验（提议）
1. 使用同一 Demo 版本、同一 Fixture、同一授权、同一机器/浏览器类型。
2. 各工具完成同一主案例的有限任务；记录3轮（仅是起步样本，不代表统计显著性）。
3. 人工独立 Review 它们的操作证据与代码可维护性。
4. S1 秒杀只比较浏览器 UI 探索能力；并发一致性由独立 API 压测实验测量。
5. 结果表必须标注 `NOT RUN`、`FAIL`、`PASS`、`BLOCKED`，禁止补造数值。

## 注意
浏览器 Agent 在公共 Benchmarks 上的 Task Success 与真实 QA 的 Bug Finding Precision 是不同指标；不能直接互换。
