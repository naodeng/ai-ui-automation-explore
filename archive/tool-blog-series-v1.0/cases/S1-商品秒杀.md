# S1｜商品秒杀：统一教学业务契约

> 状态：示例合同，**不是任何真实电商业务的规则**；实践时以已有 v2.0 Demo 的 `contracts/cases/S1.yaml` 为唯一详细规则基线。此处是写作摘要。

## 固定规则
Demo：初始库存 100，每个用户最多 1 笔有效成功购买；使用服务端模拟时钟；单浏览器不进行并发压测

## 跨工具复用的测试任务
1. 测试开售前/开售瞬间/售罄后的按钮和排队状态
2. 模拟接口 429、超时与重试，检查 UI 状态恢复和请求副作用
3. 由单独授权的 API 并发实验检查库存守恒、订单唯一和释放幂等

## 独立业务 Oracle
`campaign_clock + flashsale_ledger + user_order_ledger`。验证页面状态前，必须先建立服务端只读证据、事件日志或账本，再关联截图与浏览器 Trace。

## 风险与误报边界
- 核心风险：超卖、重复购买、库存泄漏、排队状态错误。
- 安全范围：禁止生产压测、无限重试、绕过限流、真实支付。
- 只看到 UI 异常时标记为 `Suspected`，只有符合业务契约、有独立证据并复现后才可 `Confirmed`。
