# AI 驱动的 Web UI 自动化测试：工具实战博客系列

**一句话定位：每个工具各写一篇，围绕 UI 自动化价值展开；探索性测试是其中一章而不是整个系列的唯一目标。**

三条读者路径：
- 新手：安装 → 操作浏览器 → 写第一个断言 → 保存 Trace → 集成 CI。
- QA 自动化工程师：工具编排 → 业务契约 → 稳定回归 → 维护与评估。
- AI-Native QA 实践者：自主探索 → 独立 Oracle → 证据治理 → 测试资产沉淀。

### 深度分级
- **完整篇**：可承担 UI 自动化主要执行/实现路径，写安装、脚本、Runner、CI、业务实践、FAQ、维护及进阶。
- **专题篇**：浏览器宿主、诊断、特定领域或辅助能力，写清楚它在自动化体系中的位置及限制，不冒充通用 Runner。
- **短篇**：基准、评估、人工辅助工具，做速览与复现实验，不强行写完整自动化教程。

### 内容原则
- 每篇**一个工具作为主角**；同时以 E1/M1/S1 三案例建立共性与差异。
- 主案例只写工具真实擅长的部分；其它两个案例列迁移练习，避免机械复制。
- 真实项目不得用于未授权探索；秒杀的性能/并发验证只能在隔离 API 压测环境进行。
- 与上一版 Codex 实施包协作，使用统一 Demo 业务契约和证据规范。
