# 15｜从三个教学 Demo 迁移到真实业务时的检查清单

> 当前包不是生产测试授权文件。迁移需单独批准真实系统范围、数据、凭证、执行策略和 SLA。

## 第一步：替换需求，不是替换 URL

- 获得真实 PRD、用户故事、历史缺陷、API/事件契约、数据字段、权限矩阵与性能 SLO。
- E1 替换价格门槛/税费/运费/取消/退款规则；M1 替换等级阈值/周期/权益生命周期；S1 替换库存/预占/释放/资格/支付规则。
- 将所有演示假设标记 `superseded`，不能将“满 100 减 20”等硬编码用到真实平台。

## 第二步：资产和隔离

- 仅接入授权 staging，与生产账号、短信、支付、发货、优惠券真权益隔离。
- 测试账号权限最小化；只读 Oracle 独立凭证；避免真实生产数据的镜像副本。
- 实施真正的网络隔离、动作级权限、审计和数据脱敏，不单靠 Prompt 和 allowlist。

## 第三步：可回退、可重置

- 先设计数据恢复机制、测试时钟/异步任务控制、订单/权益/库存的补偿。
- 不允许用生产“删除测试订单”等方式试图重置场景。
- 如果环境无法重置，不进入自主 Agent PoC。

## 第四步：业务 Oracle 与证据

- 真实后端接口/只读日志、数据库审计、事件流可能是多个权威源；必须定义优先级、最终一致性 SLA 与矛盾处理。
- 对不同版本、CPU、浏览器的差异独立记录；不要从单一前端页面作“最终成功”结论。

## 第五步：灰度 PoC

- 从 E1 的只读页面观察开始，然后选择低风险写操作；M1 当前授权先只读；S1 只做页面状态与受控单请求。
- 单独组织有审批的服务级并发实验，绝不自动扩展浏览器操作并发。
- 每轮结束人工 Review、权限审计、证据归档、恢复数据。

## 必要签字

业务负责人确认规则；测试负责人确认覆盖和判定；安全负责人确认环境与工具权限；平台负责人确认数据隔离与恢复。任何真实业务接入均需新的 Go/No-Go。
