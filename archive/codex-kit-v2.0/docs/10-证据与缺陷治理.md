# 10｜Evidence、Defect、审计与可追溯性

## 统一实体

- `RunManifest`：环境、版本、模型、run_id、case_id、seed、任务预算、限制与执行时间。
- `ActionEvent`：序号、时间、发起者、动作、目标、批准/拒绝、响应与请求 ID。
- `Evidence`：截图/Trace/网络摘要/后端 Oracle/视频等路径与 SHA-256。
- `Finding`：观察、预期规则、缺陷候选状态、复现信息与人工决策。
- `RegressionAsset`：已确认缺陷对应 Playwright/API 测试 ID；若无法转换说明原因。

## 证据存储建议

```text
artifacts/<run_id>/
├── manifest.json
├── events.jsonl
├── screenshots/
├── traces/
├── network-redacted.json
├── oracle/
├── evidence-index.json
└── findings/
```

对每个外部文件记录 SHA-256；Evidence JSON 保留 `producer, captured_at, source, data_classification, redaction_status, file_hash`。每次 Run 独立生成目录；不要覆盖上次失败证据。

## 缺陷生命周期

| 状态 | 需要什么 | 常见错误 |
|---|---|---|
| observation | 页面可观察事实和时间戳 | “按钮可见”直接称越权 |
| suspected_issue | 假设 + 预期来源 + 初步证据 | 单一截图被当最终结论 |
| reproduced_issue | 重置数据后的**独立**重复复现 | 同会话反复看一次结果 |
| confirmed_defect | 独立 Oracle + 契约依据 + 人工确认 | LLM 自己批准 Bug |

允许 `dismissed, risk_accepted, unknown` 作为独立审查结论，不等同“修复”。

## 复现可靠性

- 独立新 session、新 run_id 和同版数据种子，至少两次验证（建议值，按业务调整）。
- 失败时区分 flaky、数据污染、网络环境、Agent 漂移和真实产品缺陷。
- 生成的 Playwright 回归断言由 QA Review，不能让自动 Healer 擅自改变预期。
- 如果某个问题只在植入缺陷开关打开时发生，必须注明它是 Demo Seeded Fault，而非线上缺陷。

## 数据治理

- 本地优先，截图/Trace/HAR 可能包含 Token、Cookie、PII，不要直接上传公共 issue/云端模型。
- 必须提供证据脱敏规则、保留期限、访问权限和删除机制。
- 只读 Oracle 列出脱敏摘要而非大量原始会员/订单信息。
- 任何非测试资产和未授权 URL 访问尝试均写入审计，并触发停止策略。

## 关联要求

`REQ/Rule ID → Risk ID → Charter ID → Run ID → Action → Evidence ID → Finding ID → Human Decision → Regression Test ID`。任意缺失环节应显式标记 Not Available，不得自动补造。
