# 08｜方案 B：Midscene / Computer Use 的视觉补充

## 启用门槛

必须先完成 A 路线的稳定回归、数据 Reset 与 Oracle。没有 A 的基线时，不应上 B 做业务正确性判断。

## B 真正要证明的增益

| E1 | M1 | S1 |
|---|---|---|
| 券卡、金额、错误弹窗在窄屏溢出或遮挡 | 升级/降级徽章、权益卡、进度条和弹窗展示冲突 | 倒计时、排队、售罄 CTA 的状态切换、遮挡/闪烁 |

B 能发现“视觉线索”，但订单金额、会员授权及库存事实继续使用 A 的独立验证器。没有 PRD/设计稿的“感觉不美观”只能登记 UX 建议。

## 执行约束

1. 先锁定 Midscene 版本，确认具体 CLI/YAML/API；不得假设 v1/v2/v3 接口一致。
2. 只使用测试浏览器 Profile，和用户真实登录环境隔离。
3. 指定 4 组视口，例如 `320×640`、`375×812`、`768×1024`、`1440×900`；仅视口有价值时才增加。
4. 同一场景先运行 A 的确定性基线，再运行 B；截图命名 `run_id/case/viewport/step`。
5. `aiAssert` 失败只是候选信号，必须结合 UI 预期/设计规范及 A 层独立结果验证。
6. 视觉调用涉及外部模型前必须审批供应商、数据流、费用和脱敏方案。

## P4 实验步骤

- E1：模拟 100→99 后页面优惠卡、金额文案和 Toast 反馈；窄屏截图比对。
- M1：依次观测 Gold→Silver，区分“已领取历史券”与“新的 Gold-only 购买入口”；确认视觉与服务端授权契约不混同。
- S1：使用 Fake Clock 切换活动前/活动中/售罄，记录按钮、队列提示、刷新与焦点行为；不产生多并发写入。

## TDD 及判断门禁

- 覆盖视觉异常样例（固定字体、遮挡、弹窗关闭、对比设计稿）。
- 固定版本、同 seed 重复 3 轮，记录错误定位、非确定性与费用。
- B 有新增独立有效发现才报告“视觉增益”；如果只是重复 A 的发现，应如实报告。
- 不允许“截图判断支付成功”“徽章判断权限通过”“售罄提示判断无超卖”。
