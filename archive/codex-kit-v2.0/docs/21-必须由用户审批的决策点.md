# 21｜需要使用者与 Codex 一起确认的决策

默认选择已提供；只有**真实风险/架构/业务契约变更**才应提问，不要为了推进小问题频繁中断。

| 决策 | 默认建议 | 是否需要先批准 |
|---|---|---|
| 项目形态 | 新建独立 Local-first Demo，保留原 v1.0 | 是，在 P0 |
| 业务规则 | E1 100-20，M1 演示四级，S1 100 件限购 1 | 是，在 P1 Contract Freeze |
| 技术栈 | TypeScript/Node LTS + Playwright Test + 轻量 Web UI/API | P0 记录后批准 |
| 本地运行状态 | 简单 In-memory/SQLite，不引 PostgreSQL | 否，超出边界需批准 |
| 主浏览器工具 | Playwright Test，AI 交互入口只选一个 | 是，在 P0 |
| 视觉工具 B | P4 选择 Midscene，不影响 A | 是，尤其外部模型数据流 |
| 自主 Agent C | P5 仅受限 PoC，默认只读 | 是，必须先证明策略门禁 |
| 演示订单写入 | 只允许已审批的本地 sandbox order | 是，每次批准任务范围 |
| 会员等级改变 | 只能 Fixture 控制面执行 | 预先批准 Fixture 设计 |
| 秒杀并发 | 专门 API 受控验证，Browser Agent 不可压测 | 是，必须有负载上限/隔离 |
| 实验轮数 | 36 次计划，资源不足可先 Pilot | P6 决定真实范围 |
| Markdown 文章 | 单源网站/公众号；不生成 AI 图片 | 正式发布前人工 Review |

## 暂不需要确认就可使用的工程默认

- 测试全部 Synthetic Users，默认 localhost，拒绝未知 Origin。
- Trace/截图脱敏，Never Confirmed by Model Only。
- 每个阶段 TDD + Checkpoint + 风险登记。
- 只将真实 Run 数据填入报告，缺失写 NOT RUN。
