# 03｜业务契约：哪些是演示假设、哪些必须真实验证

> 以下是**教学 Demo 的候选业务规则**。实际开发前先冻结；适配真实业务时必须以 PRD、产品决策、API 契约和服务实现权威规则为准。

## E1：优惠券与下单（金额与幂等）

| ID | 演示规则 / 不变量 | 判定源 | 需确认的边界 |
|---|---|---|---|
| E1-R01 | 合法 C20 在小计 `>= 100` 时减 20；`99` 不减 | 报价 API | 运费/税费是否计入门槛 |
| E1-R02 | 服务端应付与订单创建返回金额一致 | 订单与报价 Oracle | 价格变更/超时行为 |
| E1-R03 | 同一用户/业务幂等键至多生成 1 个有效订单 | 订单只读账 | 有效订单的状态集合 |
| E1-R04 | 券已核销与订单终态符合约定 | 券流水 | 支付失败/取消后的恢复规则 |

默认 Mock Payment，不存在真实资金流。**支付后失败是否返券为示例可配置规则，不能凭常识假设。**

## M1：会员升降级（状态机/权益/事件）

- 演示等级：`normal → silver → gold → platinum`，可升可降；演示降级为受控时钟到期或专用测试事件。
- 当前有效等级及授权资格由服务端 `MembershipOracle` 判定，而非依靠页面徽章。
- 降级后**新购买金卡专享权益必须失效**（本演示固定）；降级前已经合法领取的优惠券是否保留，为独立规则，演示默认 `retain_until_expiry`。
- 旧浏览器页面可能缓存金卡文案，但**不可**以过期等级绕过服务端新购买授权。
- 同一事件重复消费只产生一次状态变更；乱序事件按 `event_version` 处理。
- 展示缓存可配置传播 SLA（演示 30 秒，采用受控 Fake Clock）；SLA 内可有短暂旧状态，SLA 后必须一致。

### 演示转换表

| 先前等级 | 事件 | 目标等级 | 权益断言 |
|---|---|---|---|
| silver | threshold_reached | gold | 当前可购买 Gold-only |
| gold | renewal_failed_at_period_end | silver | 当前不能再购买 Gold-only；旧领取券按合同保留 |
| gold | duplicate_downgrade_event | silver | 不可重复扣成长值/期限 |
| gold | delayed_older_upgrade_event | silver | 旧版本事件不覆盖已确认新状态 |

## S1：秒杀（状态/时钟/库存）

- 演示库存 `100` 件，单账号限购成功 `1` 件；活动开始时间采用**服务端可冻结的权威时钟**。
- UI 展示 `not_started → open → queueing → success/failed/sold_out`；显示和后端可能因异步存在短暂差异。
- `effective_success_qty <= 100`，`per_user_success_qty <= 1`；同一幂等键不可重复创建有效订单。
- 必须区分 `available`、`reserved`、`sold`、`released`、`pending_release`，并保存不可变库存流水便于独立校验。
- 订单取消、超时释放与重复回调应幂等；哪些保留库存、何时释放，依演示明确规定。
- **负载测试由隔离服务层基准单独执行**，不得让 Browser Agent 自动扩大并发或绕过风控。

## 权威 Oracle 表

| Oracle | 输入 | 返回 | 不可由什么代替 |
|---|---|---|---|
| CheckoutOracle | run_id、用户、购物车、券、订单 ID | 报价、券流水、订单终态 | 页面金额/AI 分析 |
| MembershipOracle | run_id、用户、时间、资源 | 当前等级、事件版本、历史与当前权益、授权结果 | 徽章/旧 Token 解析 |
| FlashSaleOracle | run_id、活动、用户、SKU、请求 ID | 订单、有效销量、库存分项和流水 | 按钮变灰/成功提示 |

## 待产品确认的问题（不能悄悄补规则）

1. E1 金额门槛是否包含运费与税费？优惠券何时锁定/占用/核销？
2. M1 降级到期如何处理未领取和已领取权益？展示传播 SLA 是多少？
3. S1 持有订单未支付是否消耗有效库存？待释放/补偿的最终一致 SLA 是多少？
4. “有效订单”“确认购买”“退款”“购买成功”在每个状态机中的含义是什么？
5. 任何 Mock/故障注入行为与生产规则的差异有哪些？

每次变更契约需记录版本、来源、审批人与影响测试集；不得为了让测试通过而修改预期。
