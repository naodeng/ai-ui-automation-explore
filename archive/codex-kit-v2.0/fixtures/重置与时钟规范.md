# Fixture Reset & Fake Clock 规范

目前**仅是实现规格**，未存在可执行的 Demo Reset 命令。

## 语义

`reset(case_id, seed_id, run_id)` 清除且只清除该 Run 的演示数据，以稳定 Seed 重新创建案例实体，并返回：`run_id, case_id, seed_id, fixture_version, clock_time, state_sha256`。

若重置中途发生失败必须恢复原状态并返回错误，不允许静默留下“半购物车/半会员事件/半库存账”。重置同一 Seed 两次的状态摘要应该一致（排除运行 ID、生成时间和随机审计 ID 后比较业务状态）。

`advance_clock(run_id, seconds)` 只改变测试专用时间源，不得修改 OS 时钟；如有异步任务，要按确定性调度使结果可断言。

## 权限

只有 Eval/Fixture Manager 可调用 Reset、Clock、Fault 注入；普通浏览器 Agent 只能拿已准备好的低权限 Synthetic Account 和只读 Oracle。

## TDD 验收

- 两次相同 Reset 相同业务状态 hash。
- 重置 Run A 不改变 Run B 状态。
- 非测试构建不存在专用管理路由。
- 错误的 seed 或未授权身份被拒绝并审计。
- S1 reset 后库存、订单和事件账恢复到初态；M1 old/new session 的时间点可复现。
- 运行意外终止后可用唯一 Run ID 定位副作用并安全恢复。
