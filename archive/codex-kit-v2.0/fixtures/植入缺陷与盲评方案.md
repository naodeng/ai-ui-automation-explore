# 故障注入（Seeded Faults）与误报陷阱：评估控制面

> 此文件用于**实验准备和评审者**。真正执行 A/B/C 时不能将故障真值清单放入 Agent 的可读取上下文。**本文件随交接包公开，仅用于实施准备，不能直接作为正式盲评时的秘密答案。** 在 P6 前，评估负责人须创建新的私有 Ground Truth（含随机映射），保存在 **Explorer 无权限访问的独立工作区/进程/账号中**；重新启动无先前对话上下文的 Explorer Run，并在 Run 日志中证明工作区隔离。若无法隔离，只能做非盲试点，不得宣称盲评 Recall。

| Fault | 层次 | 正确识别条件 |
|---|---|---|
| E1-F1 | UI/API | 从 100→99 后服务器仍错误保留 20 折扣（需报价真值） |
| E1-F2 | API/账本 | 同幂等键创建多笔有效沙盒订单 |
| E1-F3 | UI/网络 | 价格 API 500 时页面错误提示订单已成功 |
| E1-T1 | 合法行为 | 历史订单金额不随购物车更新 |
| E1-T2 | 合法行为 | 合法券到期前显示即将过期提示 |
| M1-F1 | 授权 | Gold→Silver 后旧 Token 仍获新的 Gold-only 资格 |
| M1-F2 | 事件 | 重复降级事件重复扣减成长值 |
| M1-F3 | UI/时钟 | 超过明确 30 秒传播 SLA 仍错误显示旧等级 |
| M1-T1 | 合法行为 | 降级前领取的券按演示规则保留至到期 |
| M1-T2 | 合法行为 | 在 30 秒传播 SLA 以内旧徽章未更新 |

| S1-T2 | 合法行为 | 排队状态在允许的传播 SLA 内暂未更新 |

## 实施要求

1. 故障注入只能启用在 localhost 可重置 Demo 的**评估控制平面**；永远不要复用真实服务的攻击或压测入口。
2. 每个 fault 的位置、触发条件、oracle、Tier、预期可见范围必须由审核者保存，不能出现在给 Explorer 的 Prompts 中。
3. 基线正常运行必须先通过；引入 fault 后对应测试 RED，而不是无条件全部失败。
4. S1-F1 属于 Tier3，只在受控服务并发评价，不能强求视觉 Agent 自己制造超卖。
5. 同一 fault 先重置再测；测试结束必须关闭全部 fault 并核对状态摘要。
6. 误报陷阱应计入 Precision 和评审分析，不应故意误导 Agent 超越真实业务规则。

## 评价原则

区分“发现相关线索”和“独立确认缺陷”。只在 Agent 有授权访问且故障真正暴露的测试层里计算 Recall 分母。不能将全部私有故障数直接当成每组必测分母。
