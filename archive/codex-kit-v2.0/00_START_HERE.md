# 立即开始：如何将整个包交给 Codex

## 你需要准备

- macOS 机器 + Codex Desktop/CLI 可读写的 **新建、空白项目目录**。
- Node.js LTS（具体版本由 Codex 检查项目兼容后锁定）、pnpm 或 npm、Git。
- 本地浏览器测试环境；第一阶段只需 Chromium + Playwright Test。
- 不需真实账户、云端浏览器、付费模型服务、第三方生产 API 或共享数据库。
- 可选：Midscene 的模型 API，仅在 P4 且获批之后配置；密钥放操作系统安全存储或 `.env.local`（Git 忽略）。

## 提供给 Codex 的第一条消息

打开 `prompts/00-总控-交给Codex.md`，将其全部复制到 Codex；告诉 Codex 当前 workspace 就是**本包所在目录**，除非你明确批准，否则先不要修改已有 `legacy-v1.0/` 文档。

第一次只让它完成 **P0：审查仓库、验证可执行条件、输出 Implementation Readiness Report**。不能直接安装十几个 Browser Agent 或开始跨域浏览。

## 阶段执行顺序

| 阶段 | 任务 | 对应 Prompt | 人工签字要点 |
|---|---|---|---|
| P0 | 阅读现有材料、列风险、核对工具版本 | 01 | Scope、权限、版本与实施依赖明确 |
| P1 | JSON Schema、业务契约、TDD 验证器 | 02 | E1/M1/S1 规则可判定、无缺失 Oracle |
| P2-E1 | 可重置电商 Demo | 03 | 金额与幂等测试真实通过 |
| P2-M1 | 可重置会员 Demo | 04 | 旧会话撤权、事件幂等可验证 |
| P2-S1 | 可重置秒杀 Demo | 05 | 库存账可核验、压测独立受控 |
| P3 | A：Playwright 确定性基线 | 06 | Trace、API、业务状态、测试复现 |
| P4 | B：视觉补充的独立试点 | 07 | 有视觉增益，且未取代业务 Oracle |
| P5 | C：自主探索受限 PoC | 08 | 预算/URL/写操作门禁，结果分级 |
| P6 | 36 次实验、成本与误报分析 | 09 | 公平可复现，不伪造结果 |
| P7 | 文档、最终评审与发布决策 | 10 | Go/Conditional Go/No-Go 有证据 |

**可提前停止**：P3 就可以发布“确定性 + AI 探索”的实战教程；B/C 是有条件的研究任务，不是 MVP 强制依赖。

## Codex 每轮提交的固定格式

1. `本轮范围`（完成与未完成）。
2. `需求和架构决策`（引用文件路径/ADR）。
3. `TDD`（RED/GREEN/REFACTOR 用例和结果）。
4. `实际修改`（文件清单、命令、结果和退出码）。
5. `证据`（日志、截图、Trace、Run ID 或明确 NOT RUN）。
6. `安全与数据`（授权、已执行写操作、是否需重置）。
7. `阻断与风险`（不得掩盖）。
8. `人工审批请求`（只能提出，不能自行批准）。

## P6 盲评前特别注意

`fixtures/植入缺陷与盲评方案.md` 包含公开演示故障设计，**不能直接用它作为盲评答案表**。评估者必须在 Explorer 无法访问的独立工作区生成新的私有故障映射，并启动全新 Agent 会话；若无法隔离，只能做非盲实验。

## 实际执行前的三次确认

- **场景规则**：是否仍采用演示规则，还是你已经批准改变？
- **环境**：是否完全隔离且数据可重置？用户授权和外部网络是否禁用？
- **判断标准**：哪一个只读 API / 业务账本是 Oracle？没有它就不能 Confirmed。

## 快速检查

```bash
python3 scripts/validate_kit.py
```

成功只表示当前包文件与示例 JSON 结构检查通过。完成后即可按照 `prompts/01-P0-仓库体检.md` 开始与 Codex 的第一轮协作。
