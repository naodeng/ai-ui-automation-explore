# AI 浏览器 / UI 探索性测试：三案例 × 三路线 × Codex 实施包

**v2.0 · 2026-11-23 · 中文开发流程 / 英文默认项目治理文档**

> 状态：**实施规格 + 可复制 Codex 提示词 + 合同/种子样例**。并非已经构建和运行通过的浏览器测试系统；未声称发现任何真实 Bug。

## 想完成什么

在**授权、隔离、可重置的本地 Demo**上，以三个案例验证：
- E1：电商满减券、结算、沙盒订单（优惠门槛、金额一致性与幂等）。
- M1：普通/银/金/铂会员升降级（等级状态、权益授权、旧会话、时间/事件一致性）。
- S1：商品秒杀（页面状态、单用户限购、请求幂等、库存守恒；并发只由受控 API 测试证明）。

分别尝试 **A 确定性 Playwright/CLI**、**B 视觉 Midscene/Computer Use**、**C 受限探索 Agent**，由相同的独立业务 Oracle 评估输出。优先完成 A，再视证据决定是否进入 B/C。

## 从哪里开始

1. 阅读 [`00_START_HERE.md`](00_START_HERE.md)：准备工作、Codex 第一条消息和阶段顺序。
2. 在一个新建的、无真实客户数据的工作区复制本包；让 Codex 阅读 `AGENTS.md`、`docs/02-端到端执行流程.md`、`docs/03-业务规则与真相源.md`。
3. 把 [`prompts/00-总控-交给Codex.md`](prompts/00-总控-交给Codex.md) **原样交给 Codex**，让其先审查边界，不要直接搭多 Agent。
4. **每次只执行一个阶段提示词**，得到测试结果与证据后再人工批准下一阶段。
5. 使用 `python3 scripts/validate_kit.py` 验证本包的文档/JSON Schema/示例结构；它**不会**运行浏览器测试。

## 不可混淆的概念

- **演示规则 ≠ 产品真实需求**：所有规则必须先经过明确的 Contract Freeze。
- **页面现象 ≠ 已确认 Bug**：业务缺陷需要权威只读 Oracle + 独立复现 + 人工确认。
- **AI 浏览器点击 ≠ 秒杀并发证明**：库存、幂等和高负载需服务层验证。
- **文档/提示词 ≠ 环境权限控制**：Shell、文件、网络、浏览器工具必须由实际沙箱和授权策略限制。
- **测试通过 ≠ 可以接入生产**：整个包仅面向非生产 PoC，后续迁移必须重新风险审查。

## 推荐用法

- 初学/单人：完成 P0–P3（业务契约、Demo、A），再选择一项 B 视觉补充。
- QA 小组：增加 P4–P6（B/C、证据与同场对照），进行 36 次计划运行的正式实验。
- 真实项目接入：仅完成独立评估后，逐项遵循 `docs/15-迁移到真实业务项目.md`，**不要**直接把 Demo 中的测试用账号、URL、接口和规则搬进生产系统。

## 安全和验收状态

当前所有实现阶段均标记 **NOT RUN**。`scripts/validate_kit.py` 只证明包内容静态自洽，不能证明浏览器工具可用、功能正确或发现缺陷。

文档归属与来源边界见 `docs/17-资料与工具核验.md`；内容适合网站与公众号 Markdown 单源再编辑发表。
