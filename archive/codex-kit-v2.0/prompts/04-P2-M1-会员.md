阅读 `AGENTS.md`、`contracts/cases/M1.yaml`、`docs/03-业务规则与真相源.md`、`docs/04-三案例详细探索指南.md`；复用已经通过 P2-E1 的 Fixture 与 Run ID 机制。

实现普通/silver/gold/platinum 的演示状态、Fake Clock、事件版本、当前有效权益（含“新购买 Gold-only”和“降级前合法领取券”两种不同资源）、旧/新会话 UI，以及只读 MembershipOracle。等级更改只能由受控 fixture 执行。

TDD：
1. RED：silver→gold 后可使用新 Gold-only；gold→silver 后**旧 Token**不能新增 Gold-only；历史券按 `retain_until_expiry` 合同保留。
2. RED：重复降级事件不重复扣值；过期 event_version 不覆盖新状态；超过演示 30 秒缓存 SLA 后不能一直显示旧等级。
3. GREEN：用最小状态机/事件账实现；不能靠“隐藏 UI 按钮”代替服务端授权。
4. REFACTOR：不同执行顺序、跨标签/重登、时间边界、两次 Reset 均有独立结果。

明确展示：看到旧金卡徽章不等于越权；授权响应仍成功才需要上升为风险候选。所有结论有 rule ID 与 Oracle 证据。
