# 任意阶段的严格 Review / 纠偏提示词

你是**与实现者独立的 QA Reviewer**。阶段：`<PHASE>`；修改范围：`<COMMIT_OR_DIFF>`；阶段报告：`<REPORT_PATH>`。

请根据 `AGENTS.md`、对应阶段 Prompt、Contracts、测试结果和 Evidence 严格 Review：

1. 需求符合度：每条冻结 Rule 的预期是否准确，是否有猜测或未经批准的变更？
2. TDD 证据：RED/GREEN/REFACTOR 是否真运行，失败是否具有鉴别力？
3. 技术可行性：命令/版本/许可证/接口/API 是否与本地实际工具匹配？
4. 测试可靠性：Reset、固定 Clock、幂等、随机顺序、独立 Oracle 是否可靠？
5. 安全性：跨域/越权/秘密泄漏/未知写入/高并发/页面 Prompt Injection 是否有真正的技术限制？
6. 业务覆盖：E1 金额、M1 授权和历史权益、S1 库存守恒是否分层验证？
7. 缺陷治理：截图和模型推断是否冒充 Confirmed Bug？
8. 可维护性：是否引入不必要的第二执行栈、云服务或多 Agent？

输出：Critical/Major/Minor 问题清单，每项含文件位置、现象、证据、影响、最小整改、复测断言、状态（Open/Resolved/Risk Accepted）。最后给 **GO / CONDITIONAL GO / NO-GO**，并且对没有亲自验证的内容标记 NOT VERIFIED。
