# 将真实实验整理成博客/公众号文章（Markdown 单源）

阅读 `legacy-v1.0/01-完整科普文章-三案例版.md`、`docs/16-文章发布与复盘.md`、`reports/P6_BENCHMARK.md`、`reports/P7_FINAL_REVIEW.md`（若存在）。

请在**保留原文章的科普风格**前提下，输出一篇适用于网站和微信公众号的 Canonical Markdown 更新稿，包含 TOC、三案例对比、Mermaid 流程/状态图、真实可脱敏的截图引用、A/B/C 方法区别、最佳实践、FAQ 和来源。

要求：
1. 只有在有真实 Run 证据时才写“发现了 N 个缺陷/Recall/成本”等结论；否则显式标明“假设/未实测”。
2. E1、M1、S1 三案例均应贯穿正文，而不是只讲下单。
3. 业务现象与 Confirmed Bug 必须区分；失败和误报也是重要发现。
4. 真实安全隔离/模型数据流需可解释，不能把 Prompt 当沙箱。
5. 不复制大段第三方仓库文档，参考资料提供原始链接和发布日期/版本。
6. 不改动已有文章原文文件；把完整新稿存入 `articles/<slug>.md`，人工确认后再替换发布源。

输出文稿，以及与原版相比的内容变更说明与仍需核查的 To-do。
