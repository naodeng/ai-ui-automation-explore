# 05｜本地环境、数据隔离与一键重置

## 目标环境（建议，不是已实现）

- 开发端：TypeScript/Node.js LTS、Vite/React 或简易网页、Playwright Test、Vitest。
- 本地服务端：Fastify/Express 等轻量 Web Server + SQLite（仅演示状态；可选使用内存状态）。
- 不使用真实支付、外部邮件、生产会员系统、CDN、真实第三方 OAuth。
- 三个案例的数据与 Run ID 显式隔离；不在多个实验运行之间复用写过的状态。

## 最小测试专用 API（建议契约，非已有接口）

| 方法 | 路径 | 行为 |
|---|---|---|
| POST | `/__test/reset` | 仅本地测试身份重置指定 run_id；失败原子回滚 |
| POST | `/__test/seed` | 用 seed_manifest + seed id 初始化数据 |
| POST | `/__test/clock` | 改变测试专用时钟；禁止影响系统时间 |
| POST | `/__test/faults` | 仅评估控制平面启用植入缺陷，普通 Agent 不可访问 |
| GET | `/__test/oracle/checkout` | 只读金额/订单/券账（脱敏） |
| GET | `/__test/oracle/membership` | 只读会员状态/授权/事件账 |
| GET | `/__test/oracle/flash-sale` | 只读活动/订单/库存账 |
| GET | `/health` | 健康状态，不能泄漏数据 |

**强制限制**：专用路由仅监听 loopback 或被隔离的测试网络，必须在非测试构建中关闭；读写凭证分离，浏览器/Agent 不得获得 reset、faults 或管理密钥。

## Fixture 生成与一致性

- 使用可重现的 seed manifest：`case_id`, `seed_id`, `run_id`, `fixture_version`, `clock_epoch`。
- Reset 必须幂等（同一 seed 两次重置得到同一数据摘要）；每次数据变化输出 correlation ID。
- P0 测试必须有三种：正常、边界、故障注入。故障植入与真值标签只供 Eval 角色使用。
- 任何测试 Run 开始前记录代码 Commit、浏览器和工具版本、数据 seed、测试时钟、模型版本与费用上限。
- 会话 Cookie、Trace、HAR、截图不得夹带生产密钥或真实个人数据。

## Reset TDD

1. RED：重置后订单仍残留 → 测试失败；同一 run 的 seed 不同 → 测试失败。
2. GREEN：完成 Reset，并返回 state checksum。
3. REFACTOR：反复重置与随机执行顺序后运行结果不受污染。
4. 阶段证据：三案例两次 Reset 的 checksum 一致；失败回滚有测试。
