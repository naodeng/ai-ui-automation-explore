# ADR-0001｜以 Playwright 为默认执行基线，视觉/Agent 为受限可选增强

- Status：**Proposed — Requires P0 approval**
- Date：2026-11-23
- Context：已有 Playwright CLI/MCP、agent-browser、Midscene、Browser Use 等多种工具。直接全部集成会引入会话漂移、证据分裂、额外权限和复杂依赖。

## Decision

1. 一期确定性执行选 Playwright Test；Codex 交互入口从 Playwright CLI/已受控宿主工具中选一个，避免双路抢同一会话。
2. 以三案例契约 + 测试 Fixture + 独立业务 Oracle 构成单一真实性基础。
3. B（Midscene/视觉工具）与 C（自主 Agent）仅在 A 基线通过后作为可选实验模块。
4. C 默认只读观察；高副作用业务操作交给受控 Fixture 或人工批准的确定性测试。
5. Evidence File Store 与业务 Demo 分离，SQLite 如需采用仅服务本地运行状态；不引入 PostgreSQL/云 DB 的提前兼容抽象。

## Consequences

- 优点：可复现、低复杂度、证据可审计、回归资产持续可用。
- 代价：早期 Agent “炫技”能力受限、需要先做可重置 Demo 和 Oracle。
- 取舍条件：如果同场对照证明其他执行器更可靠或成本显著更低，可在新 ADR 中替换，不悄悄切换。
