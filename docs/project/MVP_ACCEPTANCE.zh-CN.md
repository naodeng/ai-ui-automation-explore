# MVP 验收与 DoD（TDD）

## 业务契约
- [ ] 三份 YAML 的模拟规则已经人工 Review。
- [ ] 正反例 JSON Schema 校验通过，缺陷不能未经证据和人工批准就被确认为 confirmed。
- [ ] 所有 Demo 都有确定性重置、独立账号和 Fake Clock。

## 三业务实例
- [ ] E1：99/100 优惠边界、金额变更、重复提交、订单与券账本状态。
- [ ] M1：银→金和金→银状态、旧会话撤权、历史券有效性、重复/乱序事件。
- [ ] S1：开售前/售罄、限购、订单幂等、库存守恒、取消/超时库存释放。

## 自动化与证据
- [ ] Playwright 基线可独立执行、无用例顺序依赖。
- [ ] UI、API、账本有独立断言，不能用 Agent 文字推断代替。
- [ ] 真实执行包含工具版本、commit、种子、时间、Run ID、脱敏截图/Trace。
- [ ] 在隔离环境验证异常处理和错误恢复，秒杀并发须另行审批。

## 内容发布
- [ ] 主力工具有实际安装/Quick Start 命令和错误排查记录。
- [ ] 每篇文章主案例完整、另两案例适用性/边界清楚。
- [ ] FAQ、CI/CD、维护、安全限制有可核验资料。
- [ ] 技术 Review、QA Review、编辑 Review、人工批准后再外部发布。
