# ai-ui-automation-explore 项目 Roadmap 与 MVP

| 阶段 | 实施内容 | 验收条件 |
|---|---|---|
| P0 | 仓库体检、工具/许可证/遥测核验、Demo 业务假设审查 | 人工批准 readiness、风险登记和版本锁定计划 |
| P1 | Case Contract / JSON Schema / Seed / Fake Clock / 只读 Oracle 设计 | 正反例 TDD；无权更改核心业务规则 |
| P2 | 三个独立、可重置的 Demo（E1/M1/S1） | 每个 Demo 关键规则有真实红绿重构证据；重置前后一致 |
| P3 | 确定性 Playwright UI/API 基线 | 三案例 P0 路径自动化，Trace、实际业务断言和 CI 结果可复查 |
| P4 | Demo 完成门禁通过后，开展 Midscene / Computer Use 等视觉实验 | E1/M1/S1 已批准规则均可运行；完成后重跑 P3 基线，再对复杂控件/视觉场景同条件对比，呈现误报和成本 |
| P5（MVP 后，延后） | 受限 Browser Agent 探索 PoC | MVP v0.1–v0.3 全部功能与验收完成后，另行批准运行时和目标；验证环境级权限、任务预算、独立复现与越权阻断 |
| P6（P5 后） | 三条技术路线对照研究 | 使用统一 Seed、Fake Clock 和评估指标；公开失败与不可比情形；未执行的路线标记 `NOT RUN` |
| P7 | 文章最终 Review 与发布 | 对已形成的文章完成官方资料核对、技术/QA/编辑三审和人工批准；写作从 P3 起随证据推进，不等到 P7 才开始 |

## 内容与工程并行

P0–P4 构成 MVP v0.1–v0.3 的实施阶段。**P5 是 MVP 完成后的可选 Agent 能力实验，在全部 MVP 功能和验收完成前不执行；它是 MVP 之后最后一个新的执行能力阶段。** 当前已完成的 OrbStack 隔离基础层仅作为可选实验记录，不等于 P5 已启动或完成，也不是后续 P5 的指定运行时。P6 是依赖 P5 结果的路线评估；如果 P5 未获批或未运行，C 路线保持 `NOT RUN`，不得宣称完成三路线对比。P7 是最终审查与发布门槛。MVP 阶段可以推进 A/B 草稿；C 路线草稿先保留，待 P5 实际执行后再补写。

## Demo 完成门禁

后续视觉、工具对比和探索性测试均以稳定的 E1/M1/S1 Demo 为目标环境。进入 P4 前，三个 Demo 中所有已批准且明确的规则都必须有可重置的 Seed/Run、对应 UI/API 路径、独立只读 Oracle 和可复核证据；完成这些行为后重新运行 P3 确定性基线。未获批准的 `unknowns_to_approve` 不因“完成 Demo”而自动补成业务规则，需先单独确认具体合成行为。当前 P4 本地 Mock 干跑只验证候选复核流程，不满足此门禁，也不算视觉评估。

| 项目阶段 | 同步推进的内容 |
|---|---|
| P3 确定性基线 | Playwright Test 实战；确定性路线文章中已有基线证据支持的部分 |
| P4 视觉实验 | 视觉路线文章和实际参与实验的视觉工具文章 |
| P5（MVP 完成后）受限 Agent 探索 | 在 MVP v0.1–v0.3 全部完成并单独获批后，才推进自主 Agent 路线文章和实际参与 PoC 的工具文章；运行时隔离方式按实际环境决定，不指定 OrbStack |
| P6（P5 后）三路线对照 | P5 实际证据产生后，再完善三案例科普与路线比较；未运行路线保留 `NOT RUN` |
| P7 最终审查 | 完成技术、QA、编辑 Review，等待人工定稿和发布批准 |

## MVP 范围

- **v0.1（准备）**：本包的项目文档、三案例业务契约和 Schema；P0 及工具研究准备。
- **v0.2（基础）**：可运行三个 Demo、确定性测试基线；先完成 Playwright Test、Playwright CLI、Playwright MCP、agent-browser 的可复现使用。
- **v0.3（进阶）**：ego-lite、Midscene、Computer Use 等视觉路线实验与验收。完成 v0.3 全部功能和验收后，MVP 才算完成；自主 Agent 的 P5 不属于 MVP，延后到 MVP 完成后单独启动。
- **v1.0（稳定研究方法）**：24 工具目录持续维护、主力工具实际教程、可复现实验与证据规则稳定。**不要求 24 个工具全部成为运行时依赖，也不强制全部深度集成。**

每个阶段均要求 TDD（RED→GREEN→REFACTOR）、实际命令/退出码、可定位证据和人工审批。未执行的工作必须标注 `NOT RUN`。详细 Epic 与 Prompt 见 `docs/lab/13-路线图与Codex任务拆分.md`、`prompts/lab/`。
